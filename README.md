# Content Forge

Техническое задание (PRD) на разработку платформы «Контент-завод» для Lovable

1. Общее описание системы

«Контент-завод» — это B2B-платформа для автоматизированного сбора, фильтрации, смыслового анализа и мультиформатной переработки экспертного контента (YouTube, Telegram, статьи, аудио) в готовые публикации.

Система решает задачу создания регулярного контента без высоких затрат времени экспертов за счет автоматической транскрибации, выявления резонансных тем, фиксации позиции эксперта компании и генерации готовых публикаций по стилевым шаблонам.

2. Архитектура и стек технологий

Frontend & UI (в Lovable): React, Tailwind CSS, Shadcn UI, Lucide Icons, TanStack Query.

Backend & Database: Supabase (PostgreSQL, Supabase Auth, Row Level Security, Supabase Storage, Edge Functions).

AI & LLM Services:

Google Gemini API (1.5 Pro / Flash): Извлечение смыслов, генерация дайджестов, обработка контекста длинных видео, транскрибация голосовых комментариев, генерация мультиформатных публикаций.

Google NotebookLM API / RAG-база: База знаний для хранения стилистики, 33 постулатов компании, афоризмов и образцовых статей.

Внешние интеграции:

YouTube Data API v3: Мониторинг каналов, плейлистов, получение субтитров и метаданных.

Telegram Bot API: Прием входящих ссылок и голосовых заметок от экспертов, рассылка готовых дайджестов и уведомлений.

Google Drive API / Google Docs API: Прием ручных материалов из системных папок пользователей и экспорт готовых версий.

Оркестрация / Cron-задачи: Supabase Edge Functions (или n8n) для запуска еженедельного сбора данных и рассылок.

3. Модульная структура и функциональные требования

МОДУЛЬ 1. Панель управления источниками и «Отраслевой радар»

1.1. Мониторинг и сбор источников

YouTube-модуль:

Парсинг видео с выбранных каналов (отслеживание до 28+ авторов).

Фильтрация: автоматическое исключение Shorts и дублей.

Извлечение встроенных субтитров (дорожек) напрямую через YouTube/Google API для экономии токенов LLM.

Telegram-модуль:

Сбор постов, кол-ва просмотров, реакций, комментариев и числа подписчиков с целевых каналов.

Ручной контур (Приоритетная очередь):

Отдельный модуль/папка (Google Drive или специальный плейлист/бот), куда эксперт или менеджер закидывает ссылки или файлы.

ВАЖНО: Ручные материалы не вытесняют автоматический «Топ-10/20», а идут отдельным приоритетным блоком (не ломая алгоритмы рейтингования).

1.2. Алгоритм ранжирования и формула резонанса

Расчет итогового балла (Score) материала по формуле с весовыми коэффициентами:

$$\text{Score} = (W_1 \times \text{Охват к аудитории}) + (W_2 \times \text{Глубина реакций/комментариев}) + (W_3 \times \text{Темп набора}) + (W_4 \times \text{Возраст})$$

Правило отбора в дайджест:

Отображение не фиксированного Top-10, а 20% лучших материалов за период (по закону Парето), но не менее 3-х материалов на канал/рубрику.

Наглядное объяснение позиций в рейтинге (прозрачность факторов: почему материал попал в топ).

МОДУЛЬ 2. Аналитический контур и Еженедельный Дайджест

2.1. Генерация аналитической карточки материала

Каждый отобранный материал автоматически превращается в структурированный аналитический документ, содержащий:

Метаданные: Автор, канал, дата, охват, ссылка на оригинал.

Краткая выжимка: 3–5 ключевых мыслей.

Структура и тезисы: Ключевые блоки с таймкодами и цитатами.

Смысловая оценка: Оценка полноты и убедительности выводов источника.

2.2. Интерфейс еженедельного Дайджеста

Шапка дайджеста: Фильтры по рубрикам/каналам («Кадры», «Аудит», «РОП», «Продажи»).

Расписание выпусков (Гибкий календарь):

Возможность разводить отправку дайджестов по дням недели и времени (например: «Кадры» — Пн 10:00, «Аудит» — Вт 12:00, «РОП» — Ср 14:00), чтобы не перегружать экспертов.

Разделы дайджеста:

Лучшее в Telegram (Топ по резонансу).

Топ YouTube (Топ по рейтингу).

Выбор Эксперта / Ручные материалы (Материалы вне конкурса).

Рекомендованные темы для собственного контента.

МОДУЛЬ 3. Контур фиксации позиции Эксперта («Редакционная карточка»)

3.1. Запись и привязка позиции

Виджет добавления мнения к конкретному тезису или таймкоду материала:

Голосовой ввод: Запись голосового сообщения прямо в UI или через Telegram-бота.

Текстовый ввод: Поле для заметок.

Автоматическая транскрибация голосовых сообщений (via Gemini API / Whisper) и привязка к тезису источника.

3.2. Четкое разделение смысловых контуров

В UI карточки материалы жестко разделяются на два блока:

Блок А (Источник): Факты, исходные тезисы, цитаты и таймкоды автора.

Блок Б (Позиция Эксперта):

Согласие / Возражение.

Личные аргументы, кейсы и примеры компании.

Открытые вопросы и авторские афоризмы.

МОДУЛЬ 4. Модуль производства контента (Мультиформатная генерация)

4.1. Настройка Профиля автора и Базы знаний

Подключение RAG-базы (NotebookLM / Supabase Vector Store):

33 постулата-принципа компании/эксперта.

База афоризмов, крылатых фраз и паттернов речи.

Образцовые статьи (Golden Samples) для обучения тональности (Tone of Voice).

Редактор стилистических шаблонов (Хук, Подводка, Кульминация, Вывод, Призыв к действию).

4.2. Генератор единиц контента

На основе единого контекста (Источник + Анализ + Позиция Эксперта + Стилевой профиль) система в один клик генерирует пакет готовых материалов:

Экспертная статья / Эссе (для сайта / VC / Habr).

Пост для Telegram (краткий, емкий, с хуком).

Сценарий для YouTube / Reels / Shorts (раскадровка, текст диктора).

Email-рассылка.

Тезисы для публичного выступления.

МОДУЛЬ 5. Редакционный цикл, Роли и Публикация

5.1. Управление ролями и правами (RBAC)

Владелец продукта / Продуктовик (Product Owner): Максимальные права на конкретный канал/продукт. Финально утверждает публикацию.

Эксперт: Вносит позицию, надиктовывает комментарии, дает смысловое одобрение.

Редколлегия / Редакторы: Дорабатывают тексты, правят форматирование, подготавливают шаблоны.

Администратор: Настройка API, управление интеграциями и формулами.

5.2. Канбан-доска статусов (Workflow)

Отслеживание жизненного цикла материала по статусам:

Найдено (Радар)

В дайджесте

Ожидает позицию Эксперта

В производстве (Генерация)

Согласование Продуктовиком

Готово к публикации

Опубликовано / Архив

4. Схема структуры базы данных (Supabase PostgreSQL)

channels — реестр отслеживаемых YouTube/TG каналов (id, platform, url, title, weight_factors, category).

raw_materials — собранные видео/посты (id, channel_id, external_id, title, raw_transcript, views, reactions, engagement_score, is_manual).

digests — сгенерированные дайджесты (id, category, scheduled_at, status, content_json).

expert_positions — позиции и комментарии (id, material_id, expert_id, audio_url, transcript, reaction_type).

content_outputs — сгенерированные статьи/посты (id, material_id, format, generated_text, edited_text, status, version).

style_templates — шаблоны стилей, промпты, 33 постулата, образцы (id, name, prompt_body, rules_json).
